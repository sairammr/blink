## 0. Regressions I introduced this session (fix first)

- [ ] **R1 (H) Partial current minute pollutes averages** – `blink.py` now writes the in-progress minute on every blink (live updates). `get_today_data`, `get_stats`, `get_last_10_minutes_average`, `get_today_entries_and_average`, `get_metrics_by_date` all treat that partial minute as a full entry, dragging "Today's Avg", "10-min Avg" and `min_blinks` down. Fix: exclude the current minute from averages/min (or show it separately as "this minute").
- [ ] **R2 (M) New blink detector is unvalidated** – Rewritten (baseline + close/reopen state machine, `blink.py` ~453-520). Needs a measured accuracy test (e.g. 20/50/100 manual blinks, glasses, low light, looking down) and tuning of `close_frac`, 0.7 s max closure, 3 s relearn. No automated test exists.
- [ ] **R3 (L) `$max` upsert** – after a backend restart inside the same minute the counter restarts at 0 and `$max` keeps the older value, so blinks after the restart are undercounted for that minute.
- [ ] **R4 (L) `min_ratio_recent`** attribute added to `EyeTracker.__init__` but never used – remove.

## 1. Security

- [ ] **S1 (C) Live database credential hardcoded in source and in git history** – `blink.py:35` (`DEFAULT_MONGODB_URI`, Atlas SRV URI with user+password). Present in commits `83c3a766` and `8f489fe6`. Every shipped copy of the app also contains it. *Fix:* rotate the password now; remove default; read from env / OS keychain; purge history (`git filter-repo`) or treat as permanently burned; add secret scanning.
- [ ] **S2 (C) Architecture gives every client full DB access** – the app talks to MongoDB directly with one shared credential, so any user can read/modify/delete all devices' data (the `device_id` filter is client-side only). *Fix:* put an authenticated API (per-user/device tokens, server-side authorization) between the app and the DB; DB creds never leave the server.
- [ ] **S3 (H) TLS verification disabled** – `blink.py:143` `tlsAllowInvalidCertificates=True` (added to work around the embedded Python lacking CAs). Allows MITM of the DB connection. *Fix:* ship `certifi` and pass `tlsCAFile=certifi.where()`; remove the flag.
- [ ] **S4 (H) API bound to all interfaces, no authentication** – `blink.py:781` `host='0.0.0.0'`; the app only needs loopback. Anyone on the LAN can call `/stop`, `/shutdown`, `/config`, read blink data. *Fix:* bind `127.0.0.1`; add a per-launch random token (generated by Tauri, passed to Python via env, required as header).
- [ ] **S5 (H) Open CORS + localhost API = drive-by access from any website** – `blink.py:109` `CORS(app)` allows every origin, so any web page the user visits can read blink data and POST `/stop`, `/shutdown`, `/config` (also DNS-rebinding). *Fix:* restrict origins to the Tauri origin(s), require the token from S4, validate `Host`.
- [ ] **S6 (H) Arbitrary code execution commands exposed to the webview** – `lib.rs:401-455` `run_python_file`, `run_python_code` (unused by UI) + `tauri.conf.json` `"csp": null`. Any XSS/untrusted content in the webview = RCE. *Fix:* delete both commands; set a strict CSP.
- [ ] **S7 (M) NoSQL/regex injection in date lookup** – `blink.py:378` builds `{"$regex": f"^{date_str}"}` from the request body unvalidated (also 271, 332). Crafted input (`.*`, catastrophic patterns) returns the whole device history or burns CPU. *Fix:* validate `^\d{4}-\d{2}-\d{2}$` and use range queries (`$gte/$lt`) not regex.
- [ ] **S8 (M) Unvalidated request bodies → 500s / crashes** – `blink.py:692-694` `request.json` (400/415 on bad JSON, AttributeError on lists), `int(data["threshold"])` raises on non-numeric; `/api/metrics-by-date` same. *Fix:* schema validation (pydantic/marshmallow), return 400.
- [ ] **S9 (M) Kill-by-PID-file without verifying the process** – `lib.rs:213-233` `stop_python` fallback `taskkill /F /T` / `kill -9` on whatever PID is in `%TEMP%\tauri_blink.pid`. A stale file + PID reuse (or a planted file on shared-temp systems) kills an unrelated process. *Fix:* verify image name/start time before killing; use a per-user app-data dir; use Windows Job Objects so Python dies with the app.
- [ ] **S10 (M) `/shutdown` and `/test-alert` unauthenticated debug/control endpoints** – see S4/S5. `/shutdown` doesn't even exit the process (see B9).
- [ ] **S11 (M) Predictable, privacy-weak device ID** – `blink.py:71-86` SHA-256 of the MAC (48-bit space, trivially brute-forced → real MAC recoverable), stable cross-install identifier, no salt. *Fix:* random UUID generated at first run and stored locally; or HMAC with a server-side secret.
- [ ] **S12 (M) Personal/health data with no consent, retention or deletion** – blink rate is health-related data tied to a persistent device ID, stored in a shared cloud DB. For production in India review the **DPDP Act 2023** obligations (notice, consent, purpose limitation, deletion) with legal advice. Add a consent screen, retention policy, "delete my data".
- [ ] **S13 (M) Outdated/EOL runtime** – embedded **Python 3.10.4** (Mar 2022; the 3.10 line reached end-of-life Oct 2026) with many known fixed CVEs; repo also contains an unused 3.14.2 zip. *Fix:* pick one supported Python, build the environment reproducibly in CI.
- [ ] **S14 (M) Dependency vulnerabilities** – `npm audit --omit=dev`: **lodash 4.0.0–4.17.23 (high: code injection via `_.template`, prototype pollution)**, transitive via `recharts`; `npm audit` overall reports 9 (1 low, 8 high) incl. dev tools. `npm audit fix`. *Not run:* `cargo audit`, `pip-audit` (tools not installed) – add to CI.
- [ ] **S15 (M) Unknown-provenance executables bundled** – `application/TestApp.exe` (135 MB, PE file, no readable strings tying it to this project) and `src-tauri/bin/blink.exe` (71 MB, presumably a stale PyInstaller build) are shipped in the installer via `tauri.conf.json` resources but **referenced by no code**. Cannot be audited. *Fix:* delete, or rebuild from source in CI and sign.
- [ ] **S16 (L) Flask development server in production** – `app.run(...)` (Werkzeug dev server, prints its own warning). Use `waitress` (Windows-friendly) bound to loopback.
- [ ] **S17 (L) Verbose error/log disclosure** – `traceback.print_exc()` and exception text printed/logged; `/test-alert` returns `str(e)` to the caller (`blink.py:776-780`). Log to a rotating file; return generic errors.
- [ ] **S18 (L) `debug_paths` command leaks filesystem layout** (`lib.rs:251`) – remove from release builds.

## 2. Bugs / errors

- [ ] **B1 (H) Alert popup never works** – `blink.py:100-103` `show_critical_alert` calls `root.mainloop()` where `root` is undefined → `NameError` in the thread (seen in the live log). The headline "low blink rate" notification feature is non-functional. Also `last_alert` is computed but the frontend never displays it. *Fix:* send alerts via Tauri notifications (frontend polls `last_alert` or pushes an event); delete the Tk remnants.
- [ ] **B2 (H) `/save` always fails** – `blink.py:614` `datetime.datetime.now()` but `datetime` was rebound to the class by `from datetime import datetime` (line 15–16) → `AttributeError`. Also writes to a relative `sessions/` dir (CWD-dependent, inside the install dir).
- [ ] **B3 (H) Camera failure leaves the app "running"** – `blink.py:~574` on `cap.read()` failure sets status "Camera Error" and `break`s, but `running` stays `True`: the UI shows a green "Running"/"Tracking" with a dead loop. `VideoCapture(0)` result is never checked (`isOpened()`); camera in use by another app (Teams/Zoom) fails silently. *Fix:* check at init, set `running=False`, surface error to UI, retry/backoff, camera index selection.
- [ ] **B4 (H) "Stop" doesn't release the camera** – `stop_tracking` never calls `cap.release()` (camera light stays on after `/stop`); privacy-sensitive. Only killing the process frees it.
- [ ] **B5 (H) No reconnect / retry / buffering for MongoDB** – if the first connection fails `_connected` stays `False` forever (restart required); transient write errors are swallowed (`except Exception: pass`, `blink.py` ~197-250) so data is **silently lost**; read errors return empty lists so the UI shows zeros indistinguishable from "no data". Startup also blocks up to 10 s on the ping before Flask listens. *Fix:* local SQLite/WAL buffer + background sync with backoff; explicit connection state in `/status` and UI banner.
- [ ] **B6 (H) "Last 20 Minutes" is actually last 60 minutes** – `blink.py:~287` `timedelta(minutes=60)` then slices the last 20 entries; tile/endpoint/label say 20 minutes. Also the "blinks/min" labels on averages are per-entry, not per-minute when minutes have gaps.
- [ ] **B7 (M) Status label is stale for up to 20 minutes** – `update_status` is only reached after the `MIN_ALERT_INTERVAL` (1200 s) early-return in `check_blink_rate`, so "Critical/Normal" doesn't track the rate (seen: "Critical" after a brief low period). *Fix:* update status every evaluation; rate-limit only the alert text.
- [ ] **B8 (M) Blink rate uses wall-clock since first face** – includes paused time and time with no face; `blink_rate` is a session lifetime average, not a recent window. Use a rolling window (e.g. 60 s/5 min) counting only time with a visible face.
- [ ] **B9 (M) `/shutdown` doesn't shut down** – stops tracker/DB but the process keeps running and the DB manager is unusable afterwards.
- [ ] **B10 (M) Timezone/DST fragility** – timestamps are naive local-time strings compared lexicographically; `_ensure_device` uses `utcnow()` (naive UTC, deprecated) while blinks use local time. Store UTC datetimes (BSON dates) and convert in the UI.
- [ ] **B11 (M) Frontend date bug** – `App.jsx:~282` `selectedDate.toISOString().slice(0,10)` converts to UTC; in IST a local-midnight pick queries the previous day.
- [ ] **B12 (M) Device ID can change every launch** – `uuid.getnode()` returns a random value (not stable) when no MAC is found, fragmenting a user's data into new "devices".
- [ ] **B13 (M) Sensitivity change restarts the whole backend unnecessarily** – `update_sensitivity` (`lib.rs:457-473`) stops/starts Python though `/config` already applies the threshold live (`blink.py:694-696`); `stop_python` fallback `taskkill` is spawned **without waiting**, then `start_python` runs immediately (port/PID race); `handleSensitivityChange` waits only 3 s (10×300 ms) for a backend that takes much longer to connect to Mongo + load MediaPipe → false failure.
- [ ] **B14 (M) Sync Tauri commands block the UI thread** – `update_sensitivity` (blocking `reqwest`), `run_python_*` (`.output()`) are non-async commands (run on the main thread) → window freezes. Make them `async`/`spawn_blocking`.
- [ ] **B15 (M) Chart/bar scales hard-coded** – `App.jsx` Y-axis `domain={[0, 28]}` clips values above 28 (live data already showed 41); bars cap at 30. Use auto domain.
- [ ] **B16 (M) No error states in the UI** – every fetch failure is `console.warn`; user sees stale/zero data with a green dot. Add connection/error banner, loading states, empty states. Parallel 8-request poll every 3 s with no abort/backoff.
- [ ] **B17 (L) "above average" text** – previously always "+"; now fixed in working tree – verify.
- [ ] **B18 (L) `count < 7` alert threshold & `NORMAL_BLINK_RATE=12`, `LOW_BLINK_RATE=8`** are magic numbers; typical resting rate is ~15–20/min – get clinical/product sign-off or make configurable.
- [ ] **B19 (L) Dead/unused code** – `get_config_path`, `find_blink_exe` (`lib.rs`), `id_list` (`blink.py`), `Rratio` smoothing, `update_status` partial duplicates, `blink_config.json` ×2 (values 29 and 34, read by nothing), `greet`, `public/*.svg`, `App.css` Vite/Tauri template styles (`#greet-input`, `.logo.*`), `get-pip.py`, `__pycache__` dirs.
- [ ] **B20 (L) Thread-safety** – tracker state read by Flask threads while the tracking thread mutates it, no locks (benign in CPython today, fragile).
- [ ] **B21 (L) Import-time side effects** – `blink.py:~646-652` creates the DB connection, opens the camera and **starts tracking on import**, making the module untestable and causing the camera to start before the UI asks.
- [ ] **B22 (L) Windows-only despite "cross-platform" claim** – `find_python_exe` looks for `python-3.10.4-embed-amd64` (Windows embeddable build) with a `python3` fallback name only; README Linux/macOS steps (`cd server`, `source venv/bin/activate`) don't match the repo.
